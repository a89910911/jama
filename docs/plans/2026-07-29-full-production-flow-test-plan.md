# JamaAI 全流程生产验收测试方案

> 版本：1.0  
> 编制日期：2026-07-29  
> 适用代码版本：JamaAI 1.2.8 当前候选版本  
> 目标：验证 Web 服务端版和 Windows Electron 桌面版的全部生产功能、数据安全、可恢复性与发布能力

## 1. 验收目标与结论规则

本方案不是一次普通冒烟测试，而是一次可签字的生产发布验收。最终要回答四个问题：

1. 用户能否从登录开始，完成“项目/剧本 → 角色、场景、道具 → 分镜 → 图片 → 视频 → 配音/字幕 → 整集合成 → 导出归档”的完整闭环。
2. 所有对用户开放或对外宣传的功能，是否都有真实成功路径、失败路径和失败恢复能力。
3. MySQL 服务端版、SQLite 桌面版、第三方 AI、媒体文件、FFmpeg、权限和升级迁移是否能协同工作，且不会出现假成功、数据串用或不可恢复的数据损坏。
4. 候选版本是否满足安全、性能、兼容、备份恢复、日志监控、许可证与运维要求，可以在生产环境发布和回滚。

最终结论只允许使用以下三个等级：

| 结论 | 判定条件 |
| --- | --- |
| 通过，可发布 | 所有发布阻断用例 100% 通过；无 P0/P1；第三方生产默认与备用链路均有真实成功证据；备份恢复、回滚和正式环境冒烟通过 |
| 有条件通过 | 核心链路通过，但存在已明确关闭入口、降级或由负责人书面接受的非核心 P2 风险；不得表述为“所有功能可用” |
| 不通过 | 任一生产功能未测、阻断、假成功或失败后不可恢复；存在 P0/P1；正式环境、灾备、安全或合规门禁未通过 |

“按钮可点”“接口返回 200”“AI 配置连接测试成功”都不等于功能通过。AI/媒体功能必须真实生成有效文件，完成下载、本地持久化、页面预览、数据库关联和导出校验。

## 2. 当前基线与测试缺口

### 2.1 当前代码基线

截至编制时，仓库现状如下：

| 项目 | 当前基线 |
| --- | --- |
| 后端路由 | `backend-node/src/routes/index.js` 中约 227 个路由声明 |
| 数据库迁移 | 42 个 MySQL/SQLite 迁移 |
| 后端自动化 | 39 个测试文件，2026-07-29 本地执行 204/204 通过 |
| 前端自动化 | 15 个测试文件，2026-07-29 本地执行 57/57 通过 |
| 前端框架 | Vue 3 + Vite |
| 后端 | Express + MySQL；打包桌面端使用 SQLite |
| 桌面端 | Electron 28；Windows NSIS、Portable、Lite/标准包 |
| 媒体链路 | 本地存储 + FFmpeg/FFprobe |

现有自动化主要覆盖服务逻辑、数据库兼容、供应商协议转换、任务恢复和前端工具/UI 静态规则。它们是良好的回归基线，但不能替代以下测试：

- 真实浏览器端到端测试；
- 全部后端路由的认证、权限、参数和资源归属测试；
- 真实第三方 AI 账号、余额、限流和内容策略测试；
- Electron 安装包、首次启动、升级、卸载和 SQLite 数据迁移测试；
- 正式 Nginx/HTTPS/MySQL/存储环境测试；
- 并发、长稳、磁盘耗尽、断网、服务重启和备份恢复测试；
- Web 安全、文件安全、隐私和商业分发合规测试。

### 2.2 执行前必须确认的功能目录差异

在正式执行前，由产品负责人对每项功能标记“生产 / 实验 / 本版本关闭”，形成唯一功能清单。当前至少要处理以下差异：

1. 功能文档声明画布地址为 `/film/:id/canvas`，源码保留 `DramaCanvas.vue`，但当前前端路由表没有独立画布路由。需要确认画布的正式入口与支持状态。
2. 功能说明曾将“自由创作、通用媒体素材库”描述为未公开入口，但当前 `App.vue` 已把它们放入主导航。若入口保留，就必须按生产功能完整验收。
3. README 仍描述三类 AI 配置，而当前运行时实际包含 `text`、`image`、`storyboard_image`、`video`、`tts` 五类能力。发布文档和测试矩阵必须与代码一致。
4. 2026-07-28 的历史报告仍有 TTS、参考图视频、正式 HTTPS/备份恢复和 FFmpeg 分发合规等门禁。新版本必须重新取证，不能继承旧结论。

未完成上述分类的功能一律按“生产功能”测试，不能以“实验功能”为由跳过。

- 安全、性能、容量、稳定性、兼容性、可观测性和许可证。

### 3.2 不允许模糊排除的范围

第三方服务故障不能简单归为“外部原因”。若它是生产默认或备用配置，以下情形均会阻断对应功能上线：

- 账号无权限或余额不足；
- 模型名已下线或接口协议不兼容；
- 本地参考图无法传给供应商；
- 内容授权没有完成；
- 供应商结果无法轮询、下载或持久化；
- 429、超时、5xx 后没有可恢复重试或清晰降级；
- 连接测试通过但真实生成失败。

如某供应商或模型不准备在生产支持，必须从默认配置、可选列表和对外文档中移除或明确标注，不可保留“支持”声明但跳过验收。

## 6. 自动化测试分层

### 6.1 提交级门禁

每次合并必须执行：

```powershell
cd backend-node
node --test test/*.test.js

cd ..\frontweb
node --test test/*.test.js

cd ..
.\deploy.ps1 -PreflightOnly -StrictAudit
```

要求：

- 后端、前端测试 100% 通过，无跳过和不稳定重跑；
- 前后端生产依赖无 Critical/High；Moderate 必须评估并签字；
- FFmpeg/FFprobe 版本检查通过；
- 前端生产构建通过；
- 最大 JS 包不得超过发布脚本硬上限；
- 测试日志不得包含 API Key、Cookie、JWT、数据库密码或完整敏感请求体。

### 6.2 本次应新增的自动化

| 层 | 建议位置 | 最低覆盖 |
| --- | --- | --- |
| API 集成 | `backend-node/test/integration/` | 227 个路由逐项覆盖成功、401/403、400/404、资源归属和关键冲突场景 |

## 8. 第三方 AI 真实验收

### 8.1 能力矩阵

对“生产允许选择”的每个供应商/协议逐项建立矩阵；不能只测试默认模型。

| 能力 | 必测真实操作 | 结果证据 |
| --- | --- | --- |
| 文本 | 故事、角色/场景/道具提取、分镜、提示词润色、结构化输出 | 原始请求摘要、模型、耗时、结果入库、畸形输出恢复 |
| 资产图片 | 角色、场景、道具单图/宫格、不同画幅 | 有效图片、尺寸、MIME、本地路径、参考图使用 |

| TTS | 对白、旁白、批量、中文标点、长文本 | 音频文件、编码、时长、试听、合成对齐 |

- 余额不足、模型下线、账号无权限、内容拒绝、429、超时和 5xx 都有可读错误和切换方案。

### 8.2 成功判定

一次真实生成只有同时满足以下条件才算通过：

1. UI 提交成功，模型和参数与选择一致；
2. 数据库任务、AI 请求记录和供应商任务 ID 可追踪；
3. 轮询状态不倒退，不会永久停在处理中；
4. 结果文件能被解析，类型、尺寸/时长和编码正确；
5. 文件下载到受控存储，刷新和重启后仍能使用；
6. 业务对象引用正确，可预览、切历史版本、导出；
7. 日志和页面不泄露 Key，错误不被通用文案覆盖；
8. 记录本次调用费用或可核对的用量信息。

## 9. API、数据库与文件一致性

### 9.1 全路由 API 门禁

为路由清单中的每个接口至少覆盖：

- 未登录返回 401；
- 普通用户访问管理接口返回 403；
- 合法请求成功且响应结构稳定；
- 缺字段、错类型、边界值、超限返回 4xx，而非 500；
- 不存在/已删除资源返回 404；
- 用户 A 不能通过猜 ID 读取、修改、删除用户 B 的配置、任务或资源；
- 同一请求重复提交不会产生不可解释的重复数据；
- 列表分页、排序、过滤、总数一致；
- 慢请求、并发更新和取消请求不会留下半成品；
- 错误响应不包含堆栈、SQL、绝对路径、密钥或完整供应商凭据。

所有 227 个路由必须在“路由—用例—自动化—结果”追踪表中有记录。未覆盖路由是发布阻断项。

### 9.2 数据库和媒体一致性

- 全新 MySQL、全新 SQLite 均可从 1 迁移到 42；
- 至少选三个历史版本数据库逐级升级，数据数量和关联不变；
- 重复启动迁移幂等，不重复插入提示词、账号、造型或维护记录；
- 事务失败不会出现父记录成功、子记录缺失的半完成状态；
- 删除/软删除后，列表、统计、任务和导出行为一致；
- `local_path` 必须位于受控存储根，禁止目录穿越和任意文件读取；
- 数据库记录与文件做双向孤儿扫描：记录缺文件、文件无记录都要报告；
- Base64 媒体在写库前落盘，数据库不得长期保存大体积数据 URI；
- MySQL 字符集为 `utf8mb4`，中文、Emoji、特殊文件名往返无损；
- 连接池耗尽、MySQL 断开/恢复时无静默数据丢失。

## 10. 异常、恢复与灾备演练

以下故障必须在可控环境主动注入，而不是等待偶发：

| 故障 | 期望 |
| --- | --- |
| AI 返回 401/403/429/5xx | 错误可读，任务失败或按策略退避；不假成功；可换配置重试 |
| AI 返回畸形 JSON/空结果/错误 MIME | 校验失败并保留旧数据；一次安全修复/重试不产生重复记录 |
| 视频轮询超时或结果 URL 过期 | 状态结束、错误保留、可重试；缓存失效时按配置重新上传 |
| 任务处理中重启后端/Electron | 可恢复任务继续；不可恢复任务明确失败；页面不永久转圈 |
| 用户取消任务 | 停止后续阶段；已完成结果保留；状态、请求记录和按钮同步 |
| MySQL 断连/只读/连接池满 | 请求明确失败；恢复后可继续；无部分写入 |
| 存储目录只读/磁盘满 | 生成/导出失败且不写成功状态；临时文件被清理 |
| FFmpeg/FFprobe 缺失或执行失败 | 需要媒体处理的操作失败；多片段绝不降级为第一片段 |
| 媒体文件被人工删除 | 页面给出缺失提示；导出/合成失败范围明确；可重新生成 |
| Nginx/后端进程异常 | 健康告警触发；服务恢复；静态媒体和 API 路由不混淆 |
| 发布中途失败 | 自动回滚到上一版本；数据库和媒体仍可用 |

### 10.1 备份恢复验收

至少演练一次完整恢复：

1. 创建有 MySQL 数据、图片、视频、音频和项目导出的标准项目；
2. 记录数据库版本、行数、文件数、总大小和抽样 SHA-256；
3. 执行数据库与媒体目录一致性备份；
4. 在空白恢复环境还原；
5. 启动同一候选版本并检查迁移；
6. 登录、浏览、播放、继续生成、合成和导出；
7. 对比数据数量、引用、文件和 SHA-256；
8. 记录实际 RTO 与可恢复时间点。

发布前应由业务确认 RPO/RTO。本方案建议最低目标为：RPO ≤ 1 小时、RTO ≤ 60 分钟；如现有基础设施达不到，必须在上线审批中显式记录实际目标和风险。

## 11. 非功能测试与硬门禁

### 11.1 性能与容量

若尚无业务峰值数据，先按以下最低基线测试；上线后用真实监控校准：

| 指标 | 最低门禁 |
| --- | --- |
| `/health` | p95 < 200ms |
| 非 AI 列表/详情 API | 20 并发用户下 p95 < 500ms |
| 非 AI 写操作 | 20 并发用户下 p95 < 1s |
| AI 任务受理 | 不含供应商耗时，p95 < 1s |
| 任务/进度查询 | p95 < 500ms，页面状态延迟 < 3s |
| 应用错误率 | 排除预期 4xx 后 < 1% |
| 1 小时稳定性 | 无崩溃、无连接池耗尽、无僵尸任务；RSS 稳态增长 < 20% |
| 长项目 | 20 集、每集 50 镜时页面可操作、分页正确、自动保存不阻塞 |
| Web 体验 | 桌面场景 p75 LCP < 2.5s、INP < 200ms、CLS < 0.1 |
| 前端包 | 不超过发布脚本硬上限；超警告阈值必须有优化/接受记录 |

再以预计生产峰值的 2 倍做 15 分钟压力验证。AI 压测默认使用模拟供应商，真实供应商只按账号额度验证受控并发和 429 恢复，避免无意义费用。

### 11.2 安全

- 依赖审计：Critical/High 为 0；
- 登录、改密、Cookie、会话撤销、开放重定向、暴力尝试；
- RBAC 和 IDOR：账号、AI 配置、项目、媒体、任务、日志全量横向越权；
- XSS：项目名、剧本、提示词、AI 输出、错误信息和文件名；
- SQL 注入、JSON/表单参数污染、超大请求；
- SSRF：远程图片/视频 URL 不得访问云元数据、localhost 和内网地址；
- 文件上传：扩展名/MIME/魔数、大小、压缩炸弹、ZIP Slip、路径穿越、恶意文件名；
- 静态文件：只能访问存储根，不暴露配置、数据库、日志和源码；
- CORS、HTTPS、TLS 证书、反向代理头、缓存和安全响应头；
- 密钥/JWT/Cookie/数据库口令不得出现在前端、日志、AI 记录、导出和错误页；
- 未授权 API、调试入口、栈追踪和目录列表必须关闭；
- 删除账号、项目和素材后的隐私清理符合产品声明。

发现能越权、泄密、远程执行、任意文件读写、绕过认证或破坏项目数据的问题，直接判定 P0 并停止发布。

### 11.3 兼容与桌面包

服务端至少验证正式支持的 Node 版本、MySQL 版本、Nginx 和 Linux 发行版。桌面端执行：

- Win10、Win11 x64；普通用户权限；中文用户名和含空格安装路径；
- 标准 NSIS、Portable、Lite 三种制品的安装、首启、关闭和再次启动；
- 5679 被占用时自动换端口，页面仍连接正确后端；
- 打包资源、前端、迁移、SQLite 原生模块、Sharp、FFmpeg/FFprobe 均可加载；
- 全新安装、覆盖升级、跨至少一个旧版本升级；项目、配置、媒体和登录状态按设计保留；
- 卸载时明确说明用户数据是否保留，不能静默删除不可恢复数据；
- 断网时本地项目 CRUD 可用，调用 AI 时提示准确；
- 高 DPI、多屏、睡眠唤醒、异常退出后无数据库损坏；
- Electron `nodeIntegration=false`、`contextIsolation=true` 保持有效，外部导航和权限请求受控。

### 11.4 可观测性与运维

- `/health` 同时验证应用存活和关键依赖状态，或另设 readiness；
- 每个 AI/媒体任务可用请求 ID、任务 ID、项目 ID 关联日志；
- 日志包含时间、级别、阶段、供应商状态和可操作错误，不包含密钥；
- 监控至少覆盖：进程、5xx、延迟、MySQL、磁盘、存储增长、任务失败率、任务积压、供应商错误率、证书和备份；
- 验证告警能真正送达值班人员，且有去重和恢复通知；
- `SERVER_OPERATIONS.md` 中启动、停止、发布、健康、日志、备份和回滚命令在预生产逐条走通；
- 发布后 30 分钟重点观察，异常达到回滚阈值立即回滚。

### 11.5 合规

- 核对用户素材、真人肖像、声音克隆和供应商内容政策；
- 核对提示词和参考素材发送至第三方的隐私告知；
- 核对各 AI 服务商商业使用、保存期限和地域要求；
- 核对 Electron、Node 依赖和模型相关第三方声明；
- 当前 FFmpeg/FFprobe 二进制及其编译选项必须完成 GPL/LGPL 和商业分发审查；
- 对外“本地优先/数据不出本机”表述应明确：本地保存不代表 AI 推理不上传提示词和必要参考素材。

合规未签字时，即使功能测试全部通过，也不能发布商业生产制品。

## 15. 日常回归分级

首次全量验收通过后，保持三档回归：

| 时机 | 范围 |
